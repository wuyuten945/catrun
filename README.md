# 台中市圖形路跑路線規劃系統（貓咪）

依《台中市圖形路跑路線規劃規格書》建置。輸入「行政區 × 貓咪圖形 × 里程級距」，
系統會在**真實路網**上排出一條封閉環狀路線，依規格書第二節的五大構面評分，
並產出規格書第三節要求的四項交付物。

---

## 一、怎麼用

### 網頁介面（建議）

雙擊 `run.bat`，瀏覽器開 <http://127.0.0.1:5008>

> 連接埠用 5008：5000~5002 被 SSS／MSS 佔用、5005 是 PerfMon，避開。

選好行政區、圖形、級距，按「開始規劃」。**某個行政區第一次跑要下載路網，約 1~2 分鐘**；
下載後落地快取，之後同一區再規劃只要數秒。

### 命令列

```bat
python -m catrun list                                  列出可用的區／圖形／級距
python -m catrun plan -d wuri -s cat_sit -l standard    規劃一條
python -m catrun plan -d west -s cat_paw --center 24.14,120.67   指定中心
python -m catrun batch                                 一次跑規格書要求的 8 條
```

產出全部落在 `out/`。

## 二、系統怎麼運作

```
行政區 bbox
   ↓  Overpass API（落地快取）
可跑路網圖（networkx）＋ 號誌／補給／轉運／地標
   ↓  圖形落地：中心 × 尺寸 × 旋轉角 搜尋
控制點吸附到真實路口 → A* 最短路徑串接
   ↓  級距二分 + 區間內挑最高分
封閉環狀路線
   ↓  五大構面評分
GPX / KML / Cue Sheet / 安全提醒 / 地標打卡點
```

### 為什麼要吸附到路網

規格書 2-1 寫「線條轉折需有真實路口支援，嚴禁橫越無法通行之建物」。所以圖形不是畫上去的，
是**先把圖形的每個頂點吸到最近的真實路口，再用最短路徑把相鄰路口接起來**——
產出的每一公尺都真的跑得到。

### 危險的路會自動被繞開

每條路段依 `highway` 分級、人行道有無、車道數，算一個 0~1 的安全分數
（`config.ROAD_SAFETY`）。路徑成本 = 長度 ×(1 + 1.6×(1−安全分))，
於是**危險的路在演算法眼裡比較「長」**，最短路徑會自己繞開。
綠園道、河濱步道、柳川／綠川／筏子溪一律拉到 0.95 以上——這是規格書 2-2 明列的優先路型。

### 耳朵為什麼畫得出來

控制點不是等距重取樣，而是「**圖形本身的頂點 ＋ 長邊補點**」。等距取樣會把耳尖那種
只有幾十公尺的頂點跨過去，整隻貓變成沒有耳朵的橢圓。

### 貼合度不是只看平均

整體貼得很近、但某一段暴衝兩百公尺，平均只動幾公尺，肉眼卻已經看不出是貓。
所以 `fidelity` 取「平均 ×0.5 ＋ P90 ×0.5」，局部走鐘會被抓出來。

### 里程級距是約束，不是目標

先二分找出對應級距上下限的尺寸，再在區間內取五個尺寸各自評分，挑最高的——
不是硬湊到區間中點。市區密、郊區疏，同一個級距裡小一號往往畫得比較像。

## 三、評分（規格書第二節）

| 構面 | 權重 | 系統怎麼算 |
|---|---|---|
| 圖形還原度與辨識性 | 30% | 貼合度 50%、起終點閉合 20%、折返佔比 15%、1:25000 圖上長邊 15% |
| 道路安全性與通行品質 | 25% | 路段安全加權均值 45%、每公里停等 25%、綠園道佔比 20%、無出口節點 10% |
| 里程與難度分級 | 20% | 是否落在級距 70%、累計爬升 ≤50 m/10 km 30% |
| 區域特性與地標串聯 | 15% | 寬高比契合區域風格 40%、綠帶佔比 35%、沿線地標數 25% |
| 補給與交通可達性 | 10% | 起終點距轉運節點 ≤400 m 55%、最大補給空窗 ≤3 km 45% |

每個子項的**原始數字**都會列在報告裡。只給一個總分，看的人沒辦法判斷哪裡該改。

## 四、圖形庫

| key | 名稱 | 適合的區 | 說明 |
|---|---|---|---|
| `cat_sit` | 蹲坐貓咪（側面） | 烏日、西屯 | 依手繪稿數位化。頭在左、背脊往右下、右方伸出長尾。輪廓最像貓，但需要兩支南北向短巷做耳朵 |
| `cat_face` | 貓臉（正面） | 南屯、東區 | 圓潤外廓加兩隻三角耳，沒有折返，最容易做成漂亮的封閉環 |
| `cat_paw` | 貓咪肉球 | 西區、南區 | 掌墊加四顆趾墊，全弧線，需要彎道與圓環才畫得順 |
| `cat_curl` | 蜷睡貓咪 | 烏日、西區 | 一整條流線大弧，尾巴繞回身體，適合河濱與綠園道長弧線 |

要加新圖形：在 `catrun/shapes.py` 的 `SHAPES` 加一筆，點列用 x 向右、y 向上的
0~1 正規化座標，**收尾要回到起點**（規格書 2-1 要求封閉環線）。

## 五、產出（規格書第三節）

每次規劃在 `out/` 產生五個檔：

| 檔名 | 對應規格書 |
|---|---|
| `*.gpx` | 3-1 GPX 軌跡檔，已吸附路網、無跳點 |
| `*.kml` | 3-1 KML 軌跡檔（Google Earth 可開） |
| `*_cue.csv` | 3-2 路名循序導航表：轉彎路口、路名、累計里程 |
| `*_報告.md` | 評分明細 ＋ Cue Sheet ＋ 3-3 安全提醒 ＋ 3-4 地標打卡點 |
| `*_地圖.png` | 路線圖（自繪路網底圖，不需線上圖磚） |

## 六、已知限制

* **路網品質取決於 OpenStreetMap。** 巷弄有沒有名字、有沒有人行道標記，直接影響
  Cue Sheet 與安全評分。台中市區主要道路完整，小巷的 `sidewalk`／`lit` 標記則相當稀疏。
* **爬升靠 Open-Meteo 高程 API。** 取不到就在報告上寫「未取得」，不會塞假數字。
* **搜尋不保證全域最佳。** 粗掃 25 個中心 × 7 個旋轉角，再局部爬山。
  想指定位置就用 `--center` 或網頁上的「指定中心」。
* **圖形好不好看，受限於當地路網密度。** 郊區路少，細節（耳朵、趾墊）會被拉平；
  這種情況分數會誠實反映在「圖形還原度」上，不會粉飾。
* 行政區範圍目前用矩形 bbox 近似，路線可能略微越界到鄰區。
